### Existing Docker evidence

The following completed successfully before the final startup blocker:

```text

exit code: 0
```

The full Compose build path failed with exit code 1. A subsequent targeted Compose build of `auth-service` and `parcel-service` also failed with exit code 1 at the parcel Maven package step. BuildKit output was truncated before the nested Maven cause was emitted; therefore the specific dependency or compiler error is **not claimed as known**.

Merged PR #268 independently records the same host/toolchain behavior for Compose v5.6.1: the Compose Bake path refuses Dockerfile filesystem access unless explicit `--allow=fs.read=...` permissions are supplied, while direct per-service `docker build -f deploy/dockerfiles/<service>.Dockerfile ...` is the documented workaround. This is the current leading explanation for the Compose build-path failure, but a direct parcel build was not retried here because the shared two-consecutive-failures rule had already been reached.
