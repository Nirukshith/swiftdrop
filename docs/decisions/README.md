# Architecture Decision Records (ADR)

This directory documents key architectural decisions for SwiftDrop following a **one-file-per-decision** pattern.

## Guidelines

1. **Numbering and Filename**: Files use sequential 3-digit identifiers followed by a kebab-case title (e.g. `001-role-model.md`).
2. **Lifecycle Statuses**:
   - `open`: Decision is currently proposed and under team discussion.
   - `accepted`: Decision has been agreed upon and approved.
   - `deprecated`: Decision has been superseded by a later ADR.
3. **Structure of an ADR**:
   - **Context**: Problem statement, constraints, and background.
   - **Decision**: The selected solution and technical approach.
   - **Consequences**: Positive tradeoffs, limitations, and downstream effects.
