## Mock API (MSW)

Work on the frontend without running the backend. [MSW](https://mswjs.io) intercepts API calls in the
browser with a service worker and answers them from in-memory data shaped exactly like the contracts.

```bash
npx ng serve --configuration mock
```

The browser console shows `[SwiftDrop] Mock API is ON (MSW)`. Requests without a mock handler
(for example `/api/v1/auth/**` or other services) pass through to the dev proxy as usual. Use the
existing `MockAuthService` from `shared-auth` for login; the mock customer
(`customer@swiftdrop.lk`) owns all seeded parcels.

**How it is switched on**

- `environment.useMocks` (`projects/web/src/environments/`) is `false` by default and `true` in
  `environment.mock.ts`.
- The `mock` configuration in `angular.json` swaps in `environment.mock.ts` and
  `mocks/start-mocks.mock.ts`, and copies `mockServiceWorker.js`.
- Default, development and production builds never bundle MSW or the worker, and unit tests
  never start it.

**What is mocked** (`projects/web/src/mocks/handlers/`)

| Contract | Endpoints |
| :--- | :--- |
| `contracts/openapi/parcel.yaml` | `GET/POST /api/v1/parcels`, `GET /api/v1/parcels/{id}`, `POST /api/v1/parcels/{id}/cancel`, `/api/v1/addresses` CRUD |
| `contracts/openapi/parcel-read.yaml` | `GET /api/v1/tracking/{trackingNo}` (masked), `/stream` (one SSE frame), `GET /api/v1/parcels/{id}/history`, `/receipt` (PDF), `POST/GET /api/v1/parcels/{id}/rating` |

The data covers every parcel status. Business rules follow the contracts: paging and status
filter, cancel only while `CREATED` (else `409`), same `404` for unknown and malformed tracking
numbers, rating only when `DELIVERED` and once per parcel, and the shared `ErrorResponse` shape.
State resets when the page reloads.

Useful tracking numbers: `SD-20261026-A1B2C3` (out for delivery), `SD-20261024-K7M2Q9`
(delivered), `SD-20261027-P4X8Z1` (created).

**Adding handlers for your service**

1. Add response types next to the others in `mocks/mock-models.ts`, copied from your contract.
2. Put the behaviour in a plain class or functions (like `mock-db.ts`) and unit-test it.
3. Add a `yourService.handlers.ts` in `mocks/handlers/` and spread it into `createHandlers()` in
   `mocks/handlers/index.ts`.

Keep handlers thin: they only pass the request to your logic, so the logic tests cover the
behaviour. MSW itself is not imported in Jest tests, because one of its ESM-only dependencies does
not load in this Jest setup.

`mockServiceWorker.js` is generated by MSW. After upgrading `msw`, run
`npx msw init projects/web/src/mocks/public` (the `msw.workerDirectory` entry in `package.json`
also refreshes it on install).
